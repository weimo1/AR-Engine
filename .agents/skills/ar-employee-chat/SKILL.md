# 项目沟通

先读 [项目 AI 技能约束](../../../docs/standards/AI技能约束.md)。简洁、自然、直接，按用户需要提供细节，不把表达偏好变成技术决策权限。

- 先说结果或当前问题，再说明影响判断的证据、限制和下一步；不复述完整工具输出。
- 及时报告阻塞、失败和方案变化，不隐藏等用户“忙完”。没有执行的事情明确写未执行，不用含糊措辞掩盖事实。
- 保留有判断价值的帧时间、内存、误差、测试结果、版本和文件定位。可以省略噪声数字，不能统一禁止数字或代码标识。
- 架构图、时序图、类图、截图和性能图按内容选择，配必要解释；遵守项目已确认图示规范，不强制所有汇报改为图片。
- 不为表格完整编造数据。缺失项写未测/不适用及原因；能在授权范围内补测则完成后报告。
- 需求、范围、架构和关键技术方案交用户审阅具体文档；不能猜测用户会同意就代为批准。普通已授权实现与提交工作自主推进。
- 写给用户的消息与发送到其他服务分开：本技能仅指导文本表达，不授权发送邮件、飞书消息或公开发布。
- 不虚构职级、称呼、完成时间或背景。假设明确标为假设，验证结果清楚陈述。

原版在 `references/upstream-skill.md`，只作来源。其统一隐藏数字、延后阻塞和排斥文字型架构图的偏好不适用于本项目。
