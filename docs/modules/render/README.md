# render 模块

## Bindless与GPU效果验证（2026-11-06）

用户要求记录GPU/Bindless调试方式，并确认继续按总体架构推进。本节明确后续渲染功能需要的验证方向，具体接口、图像容差和采样预算随相应切片设计。

render负责把场景对象、材质和pass的语义ID关联到rhi资源/槽位及提交证据。提供可复现的固定相机和场景、资源ID/材质ID等必要调试视图，并能按pass隔离问题。资源生命周期和工具接入职责见[rhi调试方案](../rhi/README.md#gpu与bindless调试方案2026-11-06)。

首次Bindless验证使用少量已知颜色纹理及确定的材质索引，比较实际采样结果与预期，并覆盖有效边界、容量限制、缺失资源、多帧更新和退役后复用。索引合法却读取错误纹理时，通过材质→Shader索引→槽位→资源映射查找原因。A/B绑定使用相同场景和材质语义，图像比较及适用数值检查共同提供证据。

GPU Driven阶段将可见对象与间接参数同CPU参考结果对照，分别验证空集合、全可见和容量边界。Shader布局、坐标、深度和颜色错误通过专用小场景及数值性质检查定位。截图存在、日志无错误和进程成功退出均不足以判画面通过。

必要时采用诊断Shader和有界调试Buffer记录选定pass、对象或少量异常访问，在关联提交完成后回读。容量、溢出计数、读取时机和结果解释由该切片明确，避免逐像素printf或常驻全量回读。高成本诊断和正式性能测量分别记录配置。

实现每项渲染能力时同步准备对应复现场景、调试视图和检查，运行产物关联构建、Shader变体、绑定模式、资源版本及帧/pass身份。测试输出位置遵循项目build/约定，正式长期文档保留有效结果和复现方法。

状态：2026-10-23数据与扩展边界已确认；尚未实现。确认来源A2—A5及主契约见[总体架构确认记录](../../总体架构与技术路线.md#2026-10-23-架构确认记录)，当前文档任务见[范围](../../../openspec/changes/architecture-record-confirmed-boundaries/proposal.md)。

render持有自身渲染记录、GPU资产映射、视图数据与效果缓存。场景权威与render派生边界保持A2/A4原确认；相机参数/变换及派生矩阵/历史的具体归属见R2待确认建议。执行几何、材质、光照及后处理，向rhi表达资源使用意图。它不直接依赖EnTT或编辑器，也不持有scene组件地址。

## 数据寿命与扩展边界

- 持久RenderScene与每视图可见性分开；阴影、表面捕获和GI不能仅依赖主相机可见列表。
- 每视图及效果历史、表面属性缓存和光照缓存分别管理；按变化事实决定失效，旧GPU资源仍按完成条件退役。具体更新预算与粒度待定。
- 材质求值与主视图输出分开；允许后续辅助捕获复用适用逻辑。虚拟几何和追踪表示保留接入边界，不预先实现Nanite、Lumen或ReSTIR GI。
- 几何前端与光照通过表面语义衔接；第一版GBuffer不等于永久固定唯一几何绘制路径。

图ARCH-DATA-02、确认原文与待讨论项统一在总体架构维护，不重复完整契约。资产/材质详细设计、GPU数据布局、Render Graph实现、同步、追踪和GI算法均待专项方案。

## 诊断与验证

中间输出和检查按能力提供，正常路径避免无界日志、持续回读或诊断性GPU等待。后续验证主视图外捕获、历史失效、数值/图像性质、在途回收和诊断成本；GI还需动态变化与收敛验证。未规定统一容差、性能预算或工具覆盖，尚无运行结果；不扩大[P0范围](../../../openspec/changes/bootstrap-engine-p0/proposal.md)。

## GPU Driven主路径与执行组织

2026-10-24用户明确GPU Driven为核心方向；基础GPU Scene、视锥剔除和间接绘制闭环前移；P6毕设硬性验收及具体里程碑仍待讨论，与P6扩展/四配置实验的具体关系见R3待确认建议。CPU绘制用于原型及正确性对照；具体里程碑、GPU布局与首批几何/材质范围待定，资产细节继续延期。

支持worker并行录制，实际任务粒度按负载测量；GPU可见性、变化上传、视图准备与命令录制分别考虑。自有图形pass以Dynamic Rendering执行，Compute和间接绘制之间明确资源依赖；它不替代Render Graph。每视图可见性和GI历史仍独立管理，不按交换链图像数机械复制。确认来源、图ARCH-GPU-03及参考证据见[总体架构B1—B3](../../总体架构与技术路线.md#2026-10-24-gpu-driven并行录制与dynamic-rendering确认记录)。未执行功能或性能验收。

## Graph、Shader与绑定契约

2026-10-26补记来源C3—C5见[总体架构](../../总体架构与技术路线.md#2026-10-26-tick生命周期graphshader与绑定确认补记)。轻量Graph位于render，规划资源依赖/同步/录制任务；持久资源由功能系统持有并导入，声明访问用途、子资源和Bindless集合。最小绘制原型显式执行，扩展多视图/阴影/GI前接入Graph。自动别名与多队列优化后置。

GLSL构建期并行编译，使用有限具名变体并拒绝非法组合；逻辑变体与产物身份分开，缓存覆盖include内容及工具/目标/选项。GPU专用数据核验字段偏移、对齐、步长和矩阵约定，反射工具/schema/生成方式待定。资源句柄、视图及后端绑定分开；不将资产详细设计、额外GPU间接层或接口字段提前定案。主契约与图ARCH-BIND-04统一在总体架构维护，无功能或性能测试结果。

2026-10-27的R1/R2职责细化、R3与P6关系、R4长期数值维护规则均为architect建议，待用户确认，见[待确认建议](../../总体架构与技术路线.md#2026-10-27-待确认的职责澄清建议)。本入口仅引用B节原数值及候选状态，不增加新的默认值或批准。
