# 变更：整理文档并接入 SDD 与本地独立审查准备

日期：2026-10-19。状态：实施中；最终检查与独立审查见验证记录。

## 问题与范围

现有需求、ADR、规范与工作流讨论已经形成，但缺少统一入口，若干历史表述落后于已确认依赖；OpenSpec 和 OCR 尚未形成实际操作链。

用户明确要求“把 AR engine 文档都整理好”“接入 code review 以及 SDD，开始接入一下”。本次授权覆盖文档整理和本地流程基础建设。既有 OpenSpec + 轻量 Harness、OCR 先试用方向继续有效。本次不改变引擎架构、渲染范围、错误/线程方案，不配置远程、账单或模型凭据。

## Capabilities

- 新增 `workflow-bootstrap`：文档导航、契约派生、可恢复本地工具及独立审查准备。
- 当前 `openspec/specs/` 保持为空，完成适用验证与审查后再归档本项工具能力，不录入未实现引擎愿景。

## Purpose

为 AR Engine 的日常开发提供统一文档入口、单一行为验收编辑源以及可核对输入的独立审查准备流程，让开发者能够恢复本地工具并识别文档、规格与审查记录之间的不一致，同时清楚区分本地试运行和远程强制交付保护。

## ADDED Requirements

### Requirement: 文档入口区分有效基线与参考
项目 SHALL 提供文档索引和任务入口，区分产品需求、已确认决定、草案、模板及外部参考，保留原有路径和确认范围。

#### Scenario: 开始项目任务
- **WHEN** 开发者或 AI 从根目录开始任务
- **THEN** 能定位需求、ADR、适用规范、当前状态与实际操作指南，不从外部参考执行推送等指令

### Requirement: 行为与验收单源派生
项目 SHALL 从变更提案契约块派生 OpenSpec delta，并在源变化、规格缺失或出现未知派生文件时报告不一致。

#### Scenario: 源契约更新后未重新派生
- **WHEN** proposal 的内容更新而派生规格未刷新
- **THEN** 项目检查返回非零结果并定位不一致，用户无需独立审批重复规格

### Requirement: 可恢复固定的本地工具
项目 SHALL 提供固定版本的本地安装入口，校验 OCR 二进制摘要，不修改用户级技能、凭据或付费配置。

#### Scenario: 恢复开发目录
- **WHEN** 开发者执行项目工具准备脚本
- **THEN** 安装锁定 npm 依赖、验证 OCR 摘要并能运行版本与环境检查

### Requirement: 审查输入与真实结论分离
项目 SHALL 保存审查输入指纹、冻结副本与 OCR 选择集合，并识别过期输入、缺覆盖、不完整审查及未修复阻塞项。准备完成不表示审查通过，本地一致性结果不授予远程合并资格。

#### Scenario: 输入改变或审查缺少文件
- **WHEN** 准备后源码或暂存状态改变，或报告未覆盖选中文件
- **THEN** 本地审查记录检查返回非零结果并保留原因

#### Scenario: OCR 无模型预览
- **WHEN** 执行审查准备命令
- **THEN** 只运行 delegate 选择与快照准备，不自动调用外部 OCR 模型或发布评论

## 影响与验收依据

影响根入口、现有文档状态、OpenSpec 项目配置/生成技能、本地 Python/PowerShell 工具和测试。不生成引擎源文件，不用 CPU 流程测试冒充 GPU 通过。验证计划见 test-plan.md。
