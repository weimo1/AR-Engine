# 自动运行

2026-11-10。目的：让开发不靠用户在 Codex、Claude、DeepSeek 对话之间转发内容也能连续推进。

## 思路

对话之间不互通，所以不让对话互相说话，改为让它们读写同一个仓库：

- **状态只在仓库里。** 下一步做什么看 [TASK.md](../../TASK.md) 的任务队列，做过什么看 Git 提交。不依赖任何对话的记忆。
- **每个任务一个全新的无头进程。** `codex exec` 和 `claude -p` 都能从命令行非交互运行，做完就退出。上下文只有 AGENTS.md、这一项任务和它自己读的代码，不会随任务数增长。
- **门禁由脚本跑，不听 Agent 自述。** 编译零警告加 CTest 全绿才往下走，失败日志自动喂给下一轮。
- **评审也是一个命令。** 另一个模型以只读方式看未提交差异，只报阻断级问题，结论写在最后一行，脚本据此决定返修还是提交。
- **人只在里程碑出现。** 队列里标 `[人工]` 的任务会让循环停下。

## 用法

```powershell
python scripts/autorun.py --dry-run
python scripts/autorun.py --agent codex,claude --reviewer claude,codex --trust
python scripts/autorun.py --agent codex --resume
```

## 额度用完时换人

每个角色的参数都是按顺序回退的列表。某个 Agent 以非零码退出且日志末尾出现额度字样时，脚本记下它本次运行不再可用，换列表里下一个接着做同一项任务。不需要交接文档：接手的 Agent 会被告知先看 `git status` 和 `git diff HEAD`，在半成品上继续。

列表里的 Agent 全部用完时脚本停下，工作区保持原样。等额度恢复后加 `--resume` 重跑，它允许从不干净的工作区继续第一项任务。

不会超出套餐额度：5 小时额度和周额度用完都是同一种处理，换人或停下，脚本不重试也不等待。脚本启动 Agent 时会去掉环境里的 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`CODEX_API_KEY`，避免订阅额度用完后改走按量计费。账号后台的“超额后继续按量付费”开关脚本管不到，需要自己确认是关着的。停下时终端会打印 CLI 的原话，里面有是哪种额度和恢复时间。

额度字样的匹配规则是 `scripts/autorun.py` 顶部的 `LIMIT_HINT`，还没用真实的额度耗尽输出校对过。如果某次额度用完没被识别（表现为门禁白跑三轮后停下），把那次日志末尾的原话加进去。

## 角色

编排者是脚本，不是模型，所以它不占上下文也不会跑偏。三个角色各是一次独立的无头调用，互相只通过工作区里的文件交接：

| 角色 | 参数 | 做什么 | 权限 |
| --- | --- | --- | --- |
| 测试 | `--tester`（可选） | 按任务的“验收”先写会失败的用例，不碰 `engine/` | 可写 |
| 开发 | `--agent` | 实现到测试通过，勾选任务，写提交信息 | 可写 |
| 评审 | `--reviewer`（可选） | 看未提交差异，只报阻断级问题；删测试、削弱断言、留垃圾文件也算阻断 | 只读 |

单个任务的流程：测试角色写用例 → 开发 Agent 实现 → 脚本用 clang-format 格式化改动文件 → 脚本跑 `build_checks.py`（红了带日志重试，最多 3 轮）→ 评审（最多返修一轮）→ 脚本提交 → 下一项。日志在 `build/temp/autorun/<任务号>/`，任务提交成功后自动删除，只有停下时才保留。

开发和评审用不同的模型更有价值；测试角色在任务验收写得清楚时才值得开，否则省掉。不建议再加更多角色：每多一个角色就多一次全量读代码的开销，而能挡住问题的是门禁，不是角色数量。

停止条件：队列空、遇到 `[人工]`、门禁三轮仍红、所有 Agent 额度用完、评审没给出结论、任务没被勾选、提交被钩子拒绝。停下后看日志，改任务描述或手工修，再重新运行。脚本不推送。

## 注意

- 运行前工作区必须干净（`--resume` 除外）。运行期间不要在同一工作区开别的写入对话。
- 无头命令集中在 `scripts/autorun.py` 顶部的 `AGENTS` 表。Codex 固定 `gpt-6.1-sol`、中等推理强度，并带 `--ephemeral`，不在 `~/.codex/sessions` 留会话文件。
- **沙箱与 `--trust`。** 沙箱限制 Agent 能写哪里。2026-11-10 实测：Codex 的 `workspace-write` 沙箱下 vcpkg 写不了用户目录、MSBuild 查不到 Windows SDK，也就是能改代码但编译不了。要让 Agent 自己编译调试，加 `--trust`：写入角色脱离沙箱运行（Codex 用 `--dangerously-bypass-approvals-and-sandbox`，Claude 用 `--dangerously-skip-permissions`）。这等于完全信任 Agent 在这台机器上执行任何命令，只在自己的开发机上用。评审角色始终只读。不加 `--trust` 时 Agent 只能盲写，靠脚本的门禁日志返修，慢但受限。
- Claude Code 在 Windows 命令行下需要知道 Git Bash 的位置，脚本会按 `git.exe` 的安装位置自动设置 `CLAUDE_CODE_GIT_BASH_PATH`。
- 任务写得越具体越稳：一项任务一个可提交的切片，验收写成 CTest 用例名。写不出验收的任务先标 `[人工]` 讨论。
- 在 Claude Code 桌面版里也可以不用脚本：让主对话按队列逐项派子 Agent，子 Agent 的过程不进主对话上下文，主对话只收一段结果。

旧的手工多对话模式见 [多 Agent 协作](多Agent协作与上下文.md)，仅在需要单独开架构讨论时使用。
