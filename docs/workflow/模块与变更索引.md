## 如何查具体任务

1. 按模块/领域找到 change-id，再读该 change 的 proposal、design、test-plan、tasks 和 context。
2. 步骤使用 change-id 与 tasks.md 编号定位，手工执行以用户明确任务为依据；只有采用自动化快照时才引用 assignment-id，不按聊天名称猜任务。
3. 用户安排单人写入，无需 agent-status、writer 登记或流程 gate。需要追溯自动化历史时可选用 agent-status/status，不把索引或旧工具状态当成当前实际检查结果。
4. 恢复时核对当前文件与任务输入，报告变化和仍适用的证据；无领包/释放前置，不改写旧结果或接管真实运行进程。

新变更按主责领域登记一次；同一跨模块 change 可从多个模块入口链接，需求和任务正文只维护一份。归档后更新真实归档路径，不为改分类重命名已有 change-id。
