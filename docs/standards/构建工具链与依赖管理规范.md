# 构建、工具链与依赖管理规范

文档 ID：BUILD-001。修订：草案 3。日期：2026-10-19（Asia/Shanghai）。状态：Visual Studio 2026 已确定；CMake + VS generator + MSBuild、CTest、vcpkg manifest 与基础依赖选型已于本日确认，见 [ADR-0006](../adr/0006-Windows构建采用VisualStudio2026.md) 和 [ADR-0007](../adr/0007-基础构建与第三方依赖选型.md)。其余具体规则仍为草案。未创建构建工程或安装依赖。

依据：[需求](../../渲染引擎需求.txt)、[AI 任务规则](AI任务执行规则.md) 与项目内 ADR。[旧依赖建议稿](../archive/2026-10-19/discussions/渲染引擎依赖与资源绑定方案.txt) 已移入项目并标为历史讨论，不作为竞争选型源。

## 1. 推荐组合与取舍

Windows x64 使用用户指定的 Visual Studio 2026 MSVC 工具链。已选定由 CMake 组织目标并通过 Visual Studio 18 2026 generator 生成工程，由 MSBuild 执行构建，CTest 调度测试，vcpkg manifest 管理适合的第三方依赖。此入口取代旧稿默认 Ninja 的执行入口；IDE 与 AI 命令行共用 CMake 定义，不手工维护第二份 vcxproj 配置。

| 方案 | 判断与依据 |
| --- | --- |
| CMake + VS 2026 generator + MSBuild | 已选定的主入口；[CMake 4.2 官方说明](https://cmake.org/cmake/help/v4.2/generator/Visual%20Studio%2018%202026.html) 支持 x64、实例及工具集选择 |
| CMake + Ninja | VS 也可消费 CMake/Ninja 配置；本轮不作为默认，不为普通任务增加第二套必过构建。原 Filament 案例仅作参考 |
| CMake Presets | 推荐。用受版本控制的预设统一本地与 CI 配置，[官方说明](https://cmake.org/cmake/help/latest/manual/cmake-presets.7.html) 区分项目与个人预设 |
| SCons | [Godot](https://docs.godotengine.org/en/latest/engine_details/development/compiling/compiling_for_windows.html) 使用；本项目尚无对应积累，不建议为对齐另一引擎改用它 |
| vcpkg manifest | 已选定。通过明确 baseline、features、triplet 等约束依赖；[版本规则](https://learn.microsoft.com/en-us/vcpkg/users/versioning) 不等于自动生成所有环境都相同的产物 |
| 全部 vendoring / 全部 FetchContent | 不作为默认。固定源码集成可用于少量确有必要的例外，逐项记录；不能让同一依赖存在多个互不一致来源 |

## 2. 工具链与语言

- 固定并记录 VS 2026 安装实例、MSVC/标准库工具集、Windows SDK、CMake、MSBuild、vcpkg 工具/registry 提交及 Vulkan SDK/工具版本。Ninja 仅在另有明确用途时记录，不作为主构建前置依赖。
- C++23 为项目要求，明确请求且不得静默降级，不使用浮动的 latest 模式。具体编译器版本与标准开关要通过功能探针；若只提供预览标准模式，必须明确其语义并解决与已确认基线的差异，不能隐藏为“正式完整 C++23”。
- 功能探针只覆盖实际需要能力；std::expected、std::to_underlying、std::move_only_function 是既有建议稿中的候选检查，不据此强制业务代码使用它们。
- 初始化 MSVC 开发环境后检查实际工具路径与版本。缺少 cl、头文件、链接库或 SDK 时报告具体缺项，不凭 PATH 自动切换到其他编译器。
- 运行库、架构、配置与跨模块 ABI 一致。首版建议动态 CRT（Debug /MDd，优化配置 /MD），不混链接 Debug/Release CRT；库的静态/动态链接方式与 CRT 选择分别记录，不能用一个“static”混称两者。
- 首版只维护一个必过主工具链；clang-cl 可后续作为独立、明确的兼容检查，不能在同一构建目录切换编译器。

## 3. 构建入口与目录

项目 CMakePresets.json 进入版本控制；个人绝对路径和本机覆盖放忽略的 CMakeUserPresets.json。本机配置不得静默改变受支持基线，实际运行清单要记录有效配置。

建议使用 win-vs2026-x64 配置预设，generator 为 Visual Studio 18 2026、架构 x64；构建与测试预设分别为 win-vs2026-debug、win-vs2026-relwithdebinfo。VS generator 为多配置，Debug/RelWithDebInfo 由构建/测试预设的 configuration 选择，不依赖 CMAKE_BUILD_TYPE。Release 在交付/正式性能配置时补齐，名称仅为草案。

```powershell
cmake --preset win-vs2026-x64
cmake --build --preset win-vs2026-debug
ctest --preset win-vs2026-debug
```

这些为后续约定示例，当前没有对应文件，不能声称可运行。AI/Harness 如需一键执行，应串联预检、配置、构建、测试并保留各阶段结果；不在一条命令失败后继续冒充成功。

- 使用源码外构建目录，不将生成物写入 engine/editor 源码树。
- 不同工具链/generator 分开目录；VS 多配置目录可以容纳多个构建配置，但二进制和配置专属生成物按配置隔离。缓存格式/配置不匹配时明确重建。
- 模块按实际架构建立 CMake target，用 PUBLIC/PRIVATE/INTERFACE 表达依赖；引擎不能因构建便利而反向依赖编辑器。
- 优先显式列出源码；生成文件通过实际输出与依赖关系接入。不能仓库级 glob 自动吸入第三方、测试和构建目录。
- C++ 标准、警告、include 与链接属性尽量作用于目标，避免全局参数污染第三方。项目代码建议高警告级别；第三方警告单独处理，不能为通过构建关闭项目检查。

## 4. 配置含义

| 配置 | 目的 | 证据限制 |
| --- | --- | --- |
| Debug | 日常调试与适用断言/验证层 | 不作为正式性能基线 |
| RelWithDebInfo | 优化构建、保留符号，验证优化后的行为与性能 | 不能把配置名当成断言、验证层、日志强度的证明，要记录实际选项 |
| Release | 正式交付或明确的性能比较 | 仍保留必要错误与诊断，不能移除输入校验来换速度 |

GPU 验证层、重诊断、日志强度、Shader profile 与 C++ 配置分别描述。性能比较使用相同已记录配置；不能将一次 Debug 通过等同优化构建也通过。

## 5. 依赖版本与唯一来源

- vcpkg manifest 纳入版本控制，固定 registry baseline，并记录工具提交、triplet、features 与覆盖；baseline 是版本解析约束，不等于所有直接及传递依赖的绝对版本锁文件。
- 每项依赖记录用途、直接/传递关系、实际解析版本/源码标识、配置与来源；必要的精确 overrides 说明理由，升级时复核依赖图。
- 同一库只保留一个受控来源，避免 vcpkg、手工下载和系统安装混用。新版本不能仅因“latest 修复更多”自动升级。
- 包管理尚不支持的扩展版本或特殊源码，用固定 commit/下载校验值及统一入口集成，记录例外与回归范围；不从浮动 main/master 拉取。
- Vulkan 头文件、volk/VMA、Shader 编译器和验证工具核对版本/能力，不能把 SDK 与包管理提供的不同头文件无意混用。具体来源划分在集成方案中明确。
- 新库仍按用户的关键技术选型边界审阅；普通已确认依赖的接入细节由 AI 在方案内完成，不每次重复请求授权。

## 6. AI 构建与检查约束

每次任务按改动影响选择检查：文档变更检查链接/示例；C++ 变更构建受影响目标并执行适用测试；共享头、依赖或构建配置变化扩大到相关消费者；Shader 变化按 Shader 依赖图检查。

交付前必须完成本任务适用的检查，不能把未执行、失败、跳过或缺少 GPU 统称为通过。首次建立模块或接入构建时应验证 Debug 与优化配置；修改公共配置/依赖时验证受影响配置。重复运行只在新改动或未解决疑点要求时进行。

建议初期检查职责：

1. 环境预检：实际工具路径/版本、SDK 与必要运行能力。
2. 配置/构建：目标与配置正确，失败保留完整输出。
3. CPU 检查：纯数学、序列化等按实际实现接入，CTest 未发现本应存在的测试时失败。
4. GPU 冒烟：受控场景、有限帧/超时，关联日志、数值与必要图像。无 GPU 的执行环境明确标记，不能替代所需 GPU 验收。

构建进程设置合理并行度、超时和输出目录。进程/设备测试按项目副作用安全技能执行；本轮没有运行这些测试。

## 7. 恢复与证据

构建缓存用于提速，不作为源码事实；损坏时只清理任务拥有、路径已验证的构建输出。依赖下载失败不自动改镜像/版本获取不同代码；有界重试后返回可定位状态。

构建摘要关联源码版本/未提交状态、预设、实际工具版本、解析依赖、命令、退出结果与产物位置。环境可复现先指相同受控输入能重建/核验，不承诺尚未验证的逐字节一致。

## 8. 当前状态与实施前待定项

2026-10-18 后续通过 vswhere 确认已安装 VS Community 2026 18.7.1，默认 MSVC 工具集 14.51.36231，cl 文件版本 19.51.36248.0，MSBuild 文件版本 18.7.8.30822；SDK Include 目录有 10.0.22621.0 和 10.0.26100.0。普通 PATH 未找到 cl 不代表未安装。CMake 4.2.1 能列出 VS 2026 generator。尚未实际编译、链接或验证完整 SDK/驱动能力。

重要兼容项：本机 CMake 的 CXX_STANDARD=23 映射为 c++latest，与项目禁止浮动 latest 的规则存在待解决差异，详见 ADR-0006。基础建设不得只凭配置成功认定满足 C++23 基线，必须明确实际标准开关和功能探针；本轮不放宽语言要求。

待基础建设方案落实：MSVC 与 SDK 确切版本/标准开关、依赖基线与 triplet、公共目标与产物组织、Vulkan 相关唯一来源、测试框架及最小验证场景、日志/摘要格式与实际 CI 执行环境。

确认范围包括 VS 2026 及 ADR-0007 列出的构建与依赖选型；不将选型确认扩大为本规范所有参数、预设、CRT 和检查细则均已确认。本轮不创建 CMakeLists、Presets、manifest、CI 或安装工具。
