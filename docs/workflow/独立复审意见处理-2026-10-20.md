### 误报复核方案与本轮实施

为原始发现生成绑定冻结输入、规则及内容的稳定 ID；实现者只能提交代码/测试反证，不能自填 resolved 或降低级别。独立的新模型上下文读取同一输入、原始发现及反证，逐项返回“确认缺陷 / 非缺陷 / 已由新输入修复 / 证据不足”，覆盖必须与全部待复核 ID 精确匹配，并保存原始请求身份、响应及实际用量。证据不足、缺项、截断和源变化继续阻断；原始意见永久保留，不能用过滤撤回字符串冒充复核。门槛从原始审查和独立复核证据重新推导，仍不授予本地 JSON 远程身份。

此前本节为待审阅建议。用户随后要求“你来修改一下，不要反复去调整……定位问题，然后解决，快速的”，据此实施了该处置链，未把历史建议倒记为早已实现。

实现位于 scripts/workflow_findings.py：finding-prepare 离线生成绑定输入的稳定 ID 与反证模板，再构造独立请求；finding-run 为显式、有限预算的独立 API 调用；finding-apply 只生成新 adjudicated-report，不覆盖原始报告；task_gate 重读完整原始审查、独立复核原始响应及反证重新推导。准备和应用均不读取密钥或调用模型。

仅 not_defect 且有冻结文件的精确路径、行范围和原文引用可解除对应阻塞；理由与源码引用是 AI 判断的可核对依据，不是形式化正确性证明。confirmed / insufficient_evidence / fixed_in_new_input 都不能批准旧输入；后者须验证新输入并取得完整审查。不完整原始审查不能被复核“补齐”。此首版针对 direct-api 完整审查；OCR 原生路径仍使用既有规则，不伪造互转。复核独立上下文通过独立 API 请求实现；本地记录不能抵御恶意重写全部证据，不宣称认证身份。

本轮仅使用自有临时夹具离线回归，没有执行 finding-run、没有调用付费模型或替当前项目批准任何误报。完整独立复审、服务器实跑与分支保护仍未完成；不要再用重复重跑代替缺口处置。
