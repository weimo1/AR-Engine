## 1. 当前计费边界

本次查阅的 [GitHub Actions 计费文档](https://docs.github.com/en/billing/concepts/product-billing/github-actions) 说明公开仓库的标准 GitHub 托管 runner 运行时间免费；私有仓库按账户套餐计入免费分钟及超额计费。用户已选择公开仓库，因此不将 Free 私有仓库的月分钟数当作本项目标准 runner 的月限额。

[runner 价格说明](https://docs.github.com/en/billing/reference/actions-runner-pricing) 明确 larger runners 即使公开仓库也收费，包含 GPU larger runners；套餐免费分钟不能用于该类 runner。运行任务的并发、时长、存储及服务使用政策仍有约束，不将“免费时间”表述为所有资源无限免费。

artifact、缓存和源码/LFS 分别管理；公开源码仓库不等于可以无限上传构建包、模型与截图。存储实际套餐/计量以所属账户 Billing 为准，当前未读取账户套餐或余额。删除产物不撤销此前已累积的存储计量。

OCR 的外部模型端点调用由所选服务计费/限额，独立于 GitHub Actions；自托管 GPU 也有本机资源成本。用户后续已明确授权配置 DeepSeek API，并实际执行连接与工具调用测试；该授权不等于提高账户预算、购买套餐或无限自动调用。

## 2. 推荐执行分配

| 任务 | 推荐位置 | 成本与边界 |
| --- | --- | --- |
| 每次 Commit 快速检查 | 本地 Harness/hooks | 不触发云端构建；约束 CPU、磁盘与时长 |
| VS 2026 构建与 CPU/Shader 检查 | 公开仓库标准 Windows runner | 运行时间按当前公开仓库规则免费，核实镜像实际工具链 |
| 规则/文档检查、独立 OCR 调度 | 合适的标准 runner 或受控审查环境 | 模型 token 与等待耗时单独控制 |
| 真实 GPU 检查 | 隔离的自托管 GPU 或受控本地 Harness | 查询能力、限制执行来源，提供受信结果；不默认租用付费 GPU runner |

## 3. 触发与重复执行

- 本地可以多次 Commit，达到可审阅增量再 push；不把每个中间 Commit 都变成一次完整云端构建。
- PR 检查与分支 push 不重复触发同一组重检查；主分支 push 执行必要集成验收。合并队列若使用，覆盖实际合并对象，不为省运行取消必要检查。
- 同 PR 新提交取消过期的构建/审查运行，分组含 workflow 和 PR 标识，避免误取消其他任务。主分支每个仍需交付证明的提交要有有效集成证据，不直接套用全部取消策略。[并发机制](https://docs.github.com/en/actions/concepts/workflows-and-actions/concurrency)
- 按真实影响选择检查，必要汇总检查保持可判定状态；不能用路径过滤或 Draft 跳过制造合格状态。Draft 可延后重任务，进入可合并前补齐。
- OCR 结果仅在源码、范围、规则、工具和模型等输入满足复用条件时复用；PR 描述变更不应无条件触发昂贵全量重审，代码变更也不能因省费用沿用无效结果。

## 4. 建议的初始资源上限

下表是基础建设试运行的候选值，需用冷构建/正常场景耗时校准，并记录具体配置；不是已生效的限制或性能保证。

| 资源 | 初始建议 |
| --- | --- |
| 同时执行的重构建 | 项目级最多 2 个 |
| 同时执行的本机 GPU 任务 | 1 个，避免相互影响与干扰用户 |
| job 超时 | 轻量检查 10 分钟；构建/CPU/Shader 任务 45 分钟；GPU/OCR 根据固定场景与实测另定有限预算 |
| 自动重试 | 仅可解释的网络/临时基础设施故障最多再试 1 次；代码失败与预算耗尽不自动反复重跑 |
| 产物 | 成功任务优先摘要；失败保留必要日志与差异图，不上传整个 build、依赖目录或全部资产 |
| artifact 留存 | 普通成功附件 3 天、失败附件 7 天作为初始建议；发布/基准及未解决问题的关键证据另行归档，不随临时附件到期丢失 |
| 缓存 | 固定依赖、triplet/CRT、工具链与配置形成键；不通过扩展付费缓存上限解决失效或重复问题 |

缓存仅加速，不跳过应执行的验证。不同工具链或不可信来源的缓存不能无条件用于受信构建/审查结果。

## 5. 预算与模型调用

默认不启用付费 larger/GPU runner，不自动升级套餐、购买额度或提高付费预算。GitHub Actions 与所选模型服务分别设置可用预算和额度通知；任何额外付费上限由用户明确选择，当前不假设具体美元额度。

GitHub [预算与提醒](https://docs.github.com/en/billing/concepts/budgets-and-alerts) 区分提醒与停止使用；Actions 可设置到限停止，但首次预算不追溯创建前用量，因此不能把提醒或预算字段理解为绝对零超支证明。基础建设检查实际配置，不自行变更账户账单。

OCR 必须设置实际 token/任务/请求预算，记录调用量、失败与成本估算。每 PR 与月度限额待选定模型、价格和样本测量后固定；预算耗尽的 partial 审查不能通过 ai-review。外部 PR 不自动获得无限模型调用或个人 GPU 执行权限；受控触发不要求用户逐次审批已授权的项目 AI 常规任务。

达到预算/资源上限时保留已有证据，将必需阶段标记 blocked，继续不依赖该结果的本地工作。可转移至已经批准且等效的受信执行环境；不能关闭 gate、提高容差、跳过 Review 或换付费资源绕过限制。
