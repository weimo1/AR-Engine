# ADR-0007：基础构建与第三方依赖选型

日期：2026-10-19（Asia/Shanghai）。状态：选型方向已由用户确认，版本与集成待验证。

## 决策与来源

用户在上一轮依赖建议后明确“可以，这些都可以”，并要求继续核查整个项目尚未确定的大方向。本记录确认该轮列出的工具与库，沿用已有 C++23、Vulkan 1.4、VS 2026、VMA、GLM、GLSL/SPIR-V 和 spdlog 决策。

| 能力 | 已选组合 | 接入时机 |
| --- | --- | --- |
| 构建与测试调度 | CMake + Visual Studio 18 2026 generator + MSBuild，CTest | 基础工程 |
| 依赖管理 | vcpkg manifest，固定 baseline | 基础工程；确有必要的固定源码例外另行记录 |

## 实施边界

库名与工具入口已定，不再作为候选反复讨论。具体版本、features、链接与 CRT 配置、头文件来源和构建参数由基础建设固定，并验证实际兼容性；该确认不表示已经安装、联编或运行通过。

Vulkan-Headers、volk、VMA 和 SDK 工具应明确来源与兼容关系。新扩展需要单独核查编译器、头文件、驱动和验证/抓帧工具，不能从 Vulkan 1.4 标签推导 VK_EXT_descriptor_heap 可用。VS/C++23 的已知标准开关问题仍见 [ADR-0006](0006-Windows构建采用VisualStudio2026.md)。

Validation、RenderDoc、按需 Nsight 属于开发验证工具，具体能力与版本实测；不将选用工具写成已经支持两条绑定模式的捕获与重放。

Jobs 库、CPU 反射/属性元数据、SPIR-V 反射工具、CPU 分配器、压缩纹理和流送库仍按后续实际需求决定，不构成启动前的缺失依赖。

本次确认不自动批准 [总体架构讨论稿](../总体架构与技术路线.md) 的模块划分、DLL 组织、线程方案或其他规范草案。普通版本锁定与集成工作在已选方向内推进；只有改变技术基线或重大范围时才重新讨论。
