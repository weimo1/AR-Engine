## 1. 已复现的问题

### F-01：文档检查依赖机器外部参考目录，不能直接用于干净 CI

级别：P2，接入 CI 前修复。位置：[workflow.py](../../scripts/workflow.py:137)。

check 扫描自有 docs 后，对所有非 URL 链接执行本地 exists，包括研究/规范中指向 `F:/cpp project/flower` 与 agent-skills 的绝对路径。本机有该目录所以通过，但公开仓库的干净 Windows runner 不会自动拥有用户磁盘中的参考项目。

本轮通过仅在评审进程内模拟仓库外路径不可用执行原 check，实际返回：

```text
Missing local link: Flower-Shader编译与宏机制调研.md: F:/cpp project/flower/source/engine/graphics/shader.h:25
```

没有删除/重命名真实参考目录。建议区分仓库内部必需链接与机器专属研究定位，公共资料改用固定提交链接或明确列出可选本地定位；不能为修复而关闭全部项目链接检查。增加不依赖该机器目录的夹具后再接 CI。本轮未在 GitHub runner 上运行。

### F-02：正常删除文件会使审查准备失败

级别：P2，日常使用前修复。位置：[workflow.py](../../scripts/workflow.py:277)。

prepare_review 只接受 exclude_reason=user_exclude 且匹配项目排除清单的文件。原生 OCR 会把删除项报告为 deleted；因此合法的删除变更被无差别拒绝，含修改与删除的普通任务无法完成准备，纯删除任务也没有相应审查路径。

本轮在独占临时 Git 夹具中提交初始文件，修改 main.cpp 并删除 remove.cpp，调用固定 OCR 1.13.1 与实际 prepare_review 逻辑，得到：

```text
selected: src/main.cpp (modified)
excluded: src/remove.cpp (deleted), exclude_reason=deleted
ValueError: Unexpected OCR exclusion needs review: ... src/remove.cpp ... deleted
```

只适配了夹具根目录/工具位置，未修改排除判断。建议为删除项定义独立覆盖：绑定旧版本内容/删除 diff、检查引用与调用方变化，并让纯删除任务同样可审查；不能只把 deleted 加入白名单后视为已审。增加删除与重命名回归。

## 3. 尚未完成的交付设施

1. **Commit gate**：只有手动命令，CLI 没有提交门槛操作；core.hooksPath 未配置，.git/hooks 仅 sample，没有实际 pre-commit/commit-msg。不能保证每次提交前自动检查暂存输入。
2. **CI 与受保护合并**：本地没有 .github/workflows，远程无分支引用；没有已跑通的 required checks、受信结果发布、有效独立批准与自动合并。
3. **真实 OCR 审查接入**：已有模型配置/连接历史记录，但没有从冻结输入启动实际审查、解析原生结果、判定完整性/覆盖并更新问题状态的自动链路；缺已知缺陷/正确样本评测。本轮未新增 API 调用，也不读取凭据。
4. **任务就绪与恢复**：脚本目前只有 check/doctor/derive/review-prepare/review-check，没有完整 start/resume、持久阶段、交接写入权或故障恢复门槛。tasks 勾选与 schema 文件完成不替代这些能力。
5. **最新有效审查**：旧 99 文件 pass 报告本轮核验因 workspace/index changed 被拒绝；新 packet 尚无覆盖全部选中文件的审查结论。旧 request_changes 报告有其他失效项，也不能作为当前批准。
6. **归档与交付闭环**：bootstrap 仍在 changes，未验证实际首次提交 → PR → 检查/Review → 合并 → 集成 → 归档的闭环；不得只看已勾选任务执行归档。
7. **预算与资源执行**：目前限制主要是文档/示例命令，缺少统一执行入口的实际 OCR/CI 配额、产物留存与预算耗尽状态转换。

本地 JSON 与指纹被代码/指南明确标记为一致性核验，不是身份认证；本轮没有把此已声明限制另行报告成安全机制被绕过。正式远程合并仍需真正的受信执行与平台保护。

## 4. 不属于本轮工作流选型缺口

引擎第三方库、模块架构、C++/Shader/GPU 程序和实际场景验收由对应技术文档与建设任务提供。本地工作流可先用受控检查程序验证调度、状态与阻断，不需要在本聊天重新讨论选库。实际引擎验收未接入时必须保持未就绪，不能用本轮十项工具测试替代。

## 5. 建议补齐顺序

1. 修复 F-01/F-02 并补充针对性回归；先保持当前独立审查与未归档状态。
2. 实现最小 task ready/resume、暂存输入门槛与单工作区交接；证明失败阻止普通提交，并能恢复。
3. 接通有限预算的真实 OCR 运行与原生结果适配，完成受控正/负样本，再接独立审查结果。
4. 对准备发布的实际内容完成适用检查与新审查，完成首次提交/推送，接同一检查到 Actions 和主分支保护；本轮不执行发布。
5. 在真实小变更中证明检查失败/取消/缺 Review/过期输入均不能合并，合并后集成通过才关闭任务；验证中断恢复与预算处理。
