## 1. 适用范围与规则强度

适用于 AI 在本项目中的实现、修复、重构、验证、审查与交接。用户明确调整要求时，记录新要求对既有文档的影响，不用旧项目规则拒绝有效的新指令。

| 用词 | 含义 | 处理方式 |
| --- | --- | --- |
| 必须／不得 | 强制要求 | 未满足时停止依赖该条件的阶段，不进入合并或完成状态；其他独立工作可继续 |
| 应当 | 默认采用 | 偏离时记录具体理由与影响，接受适用 AI 审查；不能借此放宽其他强制要求 |
| 建议 | 可选择的实践 | 不作为阻塞项；不得将个人偏好升级成未经确认的强制标准 |

规则强度按具体条款表述判断；文件名、skill 名称、强调排版和示例风格不能自行产生强制要求。

## 2. 六项执行规则

### AI-EXEC-01：有依据再实现

必须明确任务目标、非目标、验收及适用的已确认需求和技术方案。普通小修复可引用已确认方案及缺陷复现，不必新建整套文档。

缺少的内容若影响需求、范围、架构或关键技术选择，必须整理具体差异和建议交用户审阅；不得按未确认的新基线实施受影响部分。

检查方式：任务就绪检查与设计审查，核对引用及确认范围。

### AI-EXEC-02：先读实际代码与适用规则

修改前必须核对仓库状态、已有未提交改动、相关模块和调用方，以及适用的需求、架构、方案和工程规范。尚无代码时如实记录，不假定已有实现。

新任务先读简短入口及任务记录，再按修改范围加载细则，不要求每个任务通读全部文档。恢复会话必须核对记录与实际版本；范围扩大或规则版本变化时补读受影响资料。读取过规则不表示已经满足规则。

检查方式：实现记录、实际差异与代码审查；必要时核对输入版本。

### AI-EXEC-03：控制修改范围

不得顺带新增产品能力、引入未确认依赖、改变架构契约或混入无关重构。已确认方案内的函数拆分、局部算法实现和任务拆分由 AI 自主决定。

发现扩大范围才能解决根因时，准备方案差异、证据、收益与代价，按用户确认边界处理；不能用“修根因”作为任意重写的授权。

检查方式：核对代码与文档差异是否落在任务目标及确认方案内。

### AI-EXEC-04：按影响加载技能

必须按任务类型选择相关项目技能，不以是否由用户点名作为使用的前提：

| 修改或任务类型 | 适用技能 |
| --- | --- |
| C++ 设计、实现或审查 | `ar-cpp-oop-style`，按已确认项目规范选择内容 |
| 性能调查、热点或性能敏感设计 | `ar-cpp-hpc-optimization` |
| 涉及真实进程、文件、GPU 或编辑器输入的非平凡测试 | `ar-e2e-side-effect-safety` |
| 既有模块因新约束或反复补丁需要重审 | `ar-fresh-arch` |
| 需要外部库文档或公开代码案例 | 按需要选择 `ar-context7` 或 `ar-grep-app` |
| 项目进展与决策汇报 | `ar-employee-chat`，保留必要证据和阻塞信息 |

技能不可用或工具依赖缺失时，必须区分可用的替代证据与仍然缺失的检查，不得声称该工具已运行。低风险文档修改不要求加载全套 C++ 与 GPU 指导。

检查方式：任务适用性判断和相关产出；技能读取声明不能单独充当完成证据。

### AI-EXEC-05：用证据判断完成

必须执行改动适用的构建、测试或专项验证，并保留可定位的版本、输入、命令和结果。强制检查未执行、失败或环境不支持时，不得记录为通过。

不得通过降低验收、删除有效失败检查、替换未经确认的基准来获取通过。检查本身错误时，按独立可审查的规则变更处理。

检查方式：验证证据、CI 与适用 AI Review。具体检查集合及执行工具在后续方案中落实。

### AI-EXEC-06：留下可恢复状态

任务结束、交接或中断前，应当保存当前分支/源码状态、完成与未完成项、有效检查、已知问题、阻塞及下一步。可预期的交接必须提供这些信息；意外中断缺失时恢复流程重新核实实际状态。

不得将旧会话总结当成实际仓库与运行证据。交接信息优先补充到既有任务记录，不为每个小动作创建独立报告。

检查方式：恢复时能否定位实际状态并明确继续条件。

## 3. 用户审阅的技术方案粒度

技术方案按模块或完整能力组织，例如资源管理、场景保存加载、材质与光照等；名称仅为粒度示例，不表示其具体设计已经选定。

- AI 负责准备方案、必要图示、取舍与审查材料，由用户审阅确认。
- 方案确认后，AI 自主拆分任务并实现，不为每个函数或普通局部修复重复请求批准。
- 完整能力涉及多个模块时，方案必须说明关系和契约；过大时可以按可独立审阅的能力边界拆分。
- 改变需求或验收、跨模块契约、生命周期策略、架构或关键技术路线时，必须更新相关方案并将具体差异交用户重新确认。
- 普通局部实现变化、补充测试及无语义文档修正，不因产生新提交就自动触发人工重新审批。
