# Git 提交信息规范

2026-10-21：用户明确要求提交前缀及项目统一规则，本规则适用于启用后新产生的提交。不重写已有历史。本条独立生效，不将 Git 合并规范的其他草案升级为确认。

## 固定格式

```text
fix(workflow): 修正任务交接时的状态校验

Why: 异常输入导致交接状态无法准确恢复
What: 增加输入检查并保留失败证据
Tests: 运行相关回归并通过，详见本任务验证记录
Refs: connect-dsh-runtime
```

标题必须是 `type(scope): 具体变化`：type 和 scope 小写，scope 使用真实模块，如 workflow、render、rhi、shader、assets、scene、editor、build、docs。scope 为 1–32 个小写英文字母、数字或连字符，首字符为字母。摘要允许中文，4–72 个字符，整行最多 100 字符，无首尾空白。禁用“更新”“修改”“修复问题”等空泛摘要。

| type | 用途 |
| --- | --- |
| feat | 新增用户或开发者可观察的能力 |
| fix | 修复实际缺陷 |
| docs | 只修改文档 |
| refactor | 调整代码结构，保持对外行为 |
| perf | 有测量依据的性能改进 |
| test | 增补或修正测试 |
| build | 构建、工具链或第三方依赖 |
| ci | 持续集成与自动检查配置 |
| chore | 其他明确的仓库维护 |
| revert | 回退已有提交 |

dev、other 不作为正式类型；不能为了好看把修复写成 chore，或把未测量的重构写成 perf。一个提交围绕一个可审阅目的，不夹带无关修改。

标题后空一行，正文四个字段各出现一次且必须有实际内容：

- `Why:` 问题、触发条件或变更目的。
- `What:` 最终修改与行为，必要时写取舍。
- `Tests:` 实际执行的检查和结果；未运行必须明确写“未运行”及理由，不能用格式通过冒充测试通过。
- `Refs:` 真实 change-id、问题编号、ADR 或已有方案路径；小修没有独立任务时写明关联规范和原因，不强制新建 OpenSpec。

禁止 TODO/TBD/待补占位。破坏兼容性使用 `type(scope)!: 摘要`，另写非空 `BREAKING CHANGE:` 说明影响、迁移与回退边界。revert 的 What/Refs 必须说明被回退提交；破坏性变化和回退语义由实际审查核对，格式检查器不能判断真实性。

## 执行与限制

本仓库已使用 `.githooks`。新增 commit-msg hook 调用 `python scripts/workflow_commit_message.py --file <Git消息文件>`；不合格返回非零，拒绝普通 Git 提交。pre-commit 继续检查实际暂存树，两者不调用付费模型，也不代替独立审查。

消息模板可参考本页，暂不修改用户全局 Git 配置。AI 提交前自行准备完整说明，不能用 --no-verify 跳过。Git 自动生成的 merge/revert 标题也须编辑成项目格式，没有无条件豁免。

本地 hook 可以被绕过；远程分支保护与提交历史检查尚未因此启用。机器规则只校验格式、字段与基本占位，内容准确性、类型语义、测试真实性由任务检查及 Review 核验。当前新增 hook 未经远程实跑，不能写成服务器保护已生效。
