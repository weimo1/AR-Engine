# 自动运行

2026-11-10。目的：让开发不靠用户在 Codex、Claude、DeepSeek 对话之间转发内容也能连续推进。

## 思路

对话之间不互通，所以不让对话互相说话，改为让它们读写同一个仓库：

- **状态只在仓库里。** 下一步做什么看 [TASK.md](../../TASK.md) 的任务队列，做过什么看 Git 提交。不依赖任何对话的记忆。
- **每个任务一个全新的无头进程。** `codex exec` 和 `claude -p` 都能从命令行非交互运行，做完就退出。上下文只有 AGENTS.md、这一项任务和它自己读的代码，不会随任务数增长。
- **门禁由脚本跑，不听 Agent 自述。** 编译零警告加 CTest 全绿才往下走，失败日志自动喂给下一轮。
- **评审也是一个命令。** 另一个模型以只读方式看未提交差异，只报阻断级问题，结论写在最后一行，脚本据此决定返修还是提交。
- **人只在里程碑出现。** 队列里标 `[人工]` 的任务会让循环停下。

## 用法

```powershell
python scripts/autorun.py --dry-run
python scripts/autorun.py --agent codex --reviewer claude
```

单个任务的流程：开发 Agent 实现并勾选任务、写好提交信息 → 脚本跑 `build_checks.py`（红了带日志重试，最多 3 轮）→ 评审（可选，最多返修一轮）→ 脚本提交 → 下一项。日志在 `build/temp/autorun/<任务号>/`。

停止条件：队列空、遇到 `[人工]`、门禁三轮仍红、任务没被勾选、提交被钩子拒绝。停下后看日志，改任务描述或手工修，再重新运行。脚本不推送。

## 注意

- 运行前工作区必须干净。运行期间不要在同一工作区开别的写入对话。
- 无头命令和权限参数集中在 `scripts/autorun.py` 顶部的 `AGENTS` 表。Codex 默认 `workspace-write` 沙箱，Claude 默认 `acceptEdits` 加工具白名单；构建被沙箱挡住时在那里放宽。
- Claude Code 在 Windows 命令行下需要环境变量 `CLAUDE_CODE_GIT_BASH_PATH` 指向 `bash.exe`。
- 任务写得越具体越稳：一项任务一个可提交的切片，验收写成 CTest 用例名。写不出验收的任务先标 `[人工]` 讨论。
- 在 Claude Code 桌面版里也可以不用脚本：让主对话按队列逐项派子 Agent，子 Agent 的过程不进主对话上下文，主对话只收一段结果。

旧的手工多对话模式见 [多 Agent 协作](多Agent协作与上下文.md)，仅在需要单独开架构讨论时使用。
