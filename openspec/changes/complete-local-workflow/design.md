# 实现方案

2026-10-20 补充：用户在审阅误报复核方案后要求“你来修改一下……定位问题然后解决”。本次采用独立复核证据链，不继续调整原审查提示词，也不恢复付费调用。新增 workflow_findings.py，原 direct-api 完整结果由原始响应重算；发现 ID 绑定输入、原始结果、序号及内容，重复意见也不能合并漏项。实现者反证不是批准；新请求单独运行，原始意见与响应不改写。仅独立 not_defect 且引用冻结源码可派生 resolved；confirmed、证据不足及 fixed_in_new_input 仍阻断旧输入。task_gate 重新推导 adjudicated-report，不能靠修改派生字段放行。本轮仅实现 direct-api 完整结果的复核，不支持将 OCR 原生或截断结果直接转换为该模式；本地证据不新增远程身份认证承诺。

## 组织

保留 scripts/workflow.py 的输入冻结与检查；新增 workflow_runtime.py 负责 OCR 原生适配、任务状态、执行证据及 Commit gate。命令从同一入口路由，任务正文仍只在 OpenSpec tasks.md，不复制任务清单。

任务记录和执行日志写入忽略的 .ar-workflow；采用原子替换，保留历史运行。start/resume 核对当前输入，源码变化使旧验证/审查失效。gate 重新验证当前文件身份和原始证据，不因 state.json 自填 ready 放行；本地记录不是远程信任根。

## 输入与审查

工作区模式保留现有冻结方式；staged 模式从 Git 索引 blob 导出内容，与未暂存文件隔离。输入指纹包含父提交和实际索引树。相同输入复用完整快照，避免每次操作都生成重复副本。

OCR 在只读使用的冻结源副本上执行，Git 元数据放快照外的任务目录。复制本次所需 Git 对象和索引，不创建开发 worktree，不让评审写回原项目。原始 OCR JSON 与本项目 report 分开，校验 manifest v1、provider/model/版本/规则摘要、selected 与 completed 精确集合及所有失败/豁免、警告和发现。未知格式拒绝。

规则摘要使用工具清单中的原生身份与规范化项目 JSON 双重固定；变更规则需要复核清单。不要用极低 token 预算伪造零请求准入，多文件 planner 可能先调用模型。原生源摘要按固定版本的长度前缀字段算法核对内部一致性，同时绑定任务快照和 HEAD；这不是远程认证。

首轮保守处理所有原生 findings：保持 open，需修改与新审查，不能由实现者把 high 改成 suggestion 或直接自填 resolved。API 凭据仍只由现有用户级 DPAPI 助手读取，不进入任务或 Git。

## 提交与共享检查

pre-commit 调用 commit-check：导出实际暂存树，在受控目录执行项目链接/契约检查、Python 测试与 OpenSpec 严格校验。工具安装在原项目忽略目录，由固定版本/摘要核验后复用。工作流自身只声明自己能验证的能力；出现自有 C++/Shader 时，在实际构建命令接入前阻断相应验证。

Commit 快检与独立 Review 是不同门槛。提交快检可拦截暂存错误；交付 gate 另外要求当前输入的完整审查，不宣称 hook 无法被绕过。CI 复用同一检查入口，服务器保护另行配置及测试。

## 失败与恢复

每次显式重新验证或审查先使旧资格失效；本次失败保留记录，不允许回退到旧 pass 进入就绪。中断和恢复细则见下文补齐方案；运行失败不自动再次调用付费 API。

## 2026-10-20 后续补齐

用户进一步要求首次建设后不能每次重跑整套。日常 OCR 选择变更文件；独立 API 按代码/现行文档/参考资料分组，仅代码及删除审查单元补入当前自有调用方和适用规范。单元请求使用基线、单元正文、相关上下文、逐单元 diff、规则与模型，不使用整个仓库指纹作单元缓存键；因此无关源码变动不会一律废弃所有单元。整体运行和 gate 仍绑定完整仓库指纹。通过缓存保存原始响应及请求/响应摘要，严格重算覆盖、结论与模型，不缓存失败/截断/开放问题；CI 缓存位置只取可信默认分支工具目录，不读取 PR 提供的缓存。实际付费用量与复用的历史用量分开，review-plan 不取密钥、不调用模型。缓存是本地证据优化，不能充当远程身份。

删除项不恢复进真实源码。准备时在 snapshot/.ar-review-context/deletions/ 生成 Markdown，保存 HEAD 的完整 UTF-8 旧内容、旧 blob 身份、删除 diff，以及检查当前调用方/配置/文档引用的要求。仅接受与这些材料一一对应的原生 deleted 排除；材料本身必须被 OCR 选中，摘要纳入输入指纹。验证在单独的真实源码副本中运行，移除仅用于审查的材料，避免测试导入旧代码。非 UTF-8/超限删除明确拒绝，后续需要专门二进制审查契约。

预算耗尽不能靠放宽覆盖解除。增加 direct-api 模式：沿用固定 OCR 选择和冻结输入，整个请求只读取文件正文、diff、项目规则，没有 shell、工具调用或密钥访问能力。每批文件按长度界定，全部批次必须完整返回逐文件覆盖和结构化发现；保留每次原始 HTTP 响应及 SHA、实际模型、finish_reason、usage 与请求内容摘要。输入字节数与输出上限先作保守预算预检，累计实际用量达到上限即停止；不自动重试。该模式明确是 DeepSeek 独立上下文，不伪造 OCR native.json。gate 从原始响应重新推导结论。

远程部署目标（尚未部署，不是当前已生效状态）：先完成首次发布的有效验证与复审，再建立 main。确定性 Actions 检查不使用模型凭据；独立模型审查另使用受保护环境密钥。主分支部署后应要求 PR 和成功状态，禁用强推/删除且管理员同样受约束。远程独立 Review 来源必须实际核验，不能把本地报告上传当作受信身份。

中断、超时、OCR partial、未覆盖、未知字段、规则变化和输入变化都保留失败证据，不自动增加预算或重试模型调用。恢复命令只核对并继续明确的下一步。测试使用任务拥有的临时仓库，不向主项目注入坏代码或操作用户桌面。
