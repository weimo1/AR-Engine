# 模块长期设计模板

用于 docs/modules/<module>/README.md。复制需要的结构，删去不适用部分并说明；无代码或未测内容明确标记。行为与验收差异仍在当前 change 的 proposal 编辑，不能在这里写第二份规格。

## 状态与依据

记录本模块文档修订、适用范围、确认来源；分别说明已确认设计、未确认提案、已经验收的实现。链接产品需求、总体架构、适用 ADR 和具体 change，不将整个引用文档默认批准。

## 职责与非目标

本模块解决什么问题、服务哪些调用方、不负责哪些能力。说明主责目录及与其他模块的边界，不以目录存在推定代码已实现。

## 模块关系与依赖

给出必要的 Mermaid 依赖图，说明调用方向及禁止依赖；区分编译依赖、运行时调用和资源所有权。引用真实模块或明确标记的候选，不画无依据的完整系统。

## 稳定契约与资源生命周期

说明需要长期保持的公开接口语义、输入输出、所有者、借用与销毁责任、失败行为及兼容边界。细节以已确认设计和真实接口为准，不重复抄写全部头文件。

## 关键时序与并发

跨模块、异步、线程或 GPU 工作按需要给时序图；说明创建、使用、同步与退役。类图只在解释真实类型关系时采用，不强制所有模块绘制三类图。

## 错误与可观测性

说明可定位日志、阶段/运行标识、失败退出和必要性能/图像证据。无错误日志不能单独证明画面正确；按项目适用标准引用具体约束。

## 验证与实现边界

链接真实代码、适用检查和已交付 change；注明未实现、未测、设备限制。模块 README 不保存每次运行日志，也不以计划代替验收。

## 在途演进

链接当前 change 和相关 ADR；未实现建议单列，验收交付后再合入长期事实。任务步骤由对应 tasks.md 维护，避免重复计数。
